# `new_stock` 前端实施需求文档

## 1. 文档目标
本文档只面向前端工程师，定义 `new_stock` 新项目的前端实现范围、固定 UI 基线、组件边界、状态管理、图表接入和性能约束。

前端实施原则只有两条：
- 完整保留旧项目已经定稿的 UI 设计，不做重新设计
- 用 `Svelte 5 + TypeScript + Tauri 前端通信` 重构旧项目的脆弱渲染逻辑

### 1.1 当前仓库进度口径
- Step 1 到 Step 4 的窗口入口、真实命令、板块构建链路和盘中 watch 链路都已接入主工程
- 主窗口白屏修复后，主窗口 / 设置窗口启动链路都必须继续保留可观测启动日志，禁止重新回到“内容区静默白屏”
- 图表控制器当前仍是 Step 1 冻结的单实例占位实现；因此当前文档中的“性能”口径以结构稳定性、局部更新和回归风险收口为主，不把真实图表渲染终验写成已完成

## 2. 前端范围
前端必须实现：
- 主窗口 UI
- 独立 Settings 窗口 UI
- 指数 / 板块 / 个股切图
- 日 K / 周 K 切换
- 等权 / 市值切换
- 板块构建状态展示
- 同步状态展示
- 观点笔记区
- 盘中当天最后一根日 K 的局部更新呈现

前端不负责：
- SQLite 访问
- Longbridge 接入
- 板块算法计算
- 周 K 聚合
- 同步任务调度
- 板块构建调度
- Keychain 凭证存储

## 4. 前端技术栈
- 框架：`Svelte 5`
- 语言：`TypeScript`
- 构建工具：`Vite`
- 图表：`Lightweight Charts 5.x`
- 样式：`scoped CSS + 全局 design tokens`
- 与宿主通信：`Tauri commands + events`

不采用：
- React
- SvelteKit
- 前端直连 SQLite
- 前端自行拼装板块历史

## 5. 目录结构
前端目录固定为：

```text
new_stock/frontend/
  src/
    app/
    components/
    stores/
    services/
    charts/
    windows/
    styles/
    types/
```

推荐职责：
- `app/`：窗口挂载、listener 注册、`bootstrap` 启动顺序和启动诊断
- `components/`：纯 UI 组件
- `stores/`：领域状态
- `services/`：commands、events、数据适配
- `charts/`：Lightweight Charts 单实例控制器
- `windows/`：主窗口与设置窗口入口
- `styles/`：token、全局样式
- `types/`：固定契约类型与前端 view model

### 5.1 启动与可观测性边界
- `src/main.ts` 只负责调用 `mountMainWindow()`
- `src/settings.ts` 只负责调用 `mountSettingsWindow()`
- `src/app/` 只负责窗口初始化、listener 注册、`bootstrap` 启动顺序和错误可观测性
- 主窗口与设置窗口都必须保留最早阶段启动标记、`mount-start / mount-complete / bootstrap-failed` 诊断日志
- 必须绑定 `window.onerror` 与 `unhandledrejection`，避免桌面壳层内容区异常继续以白屏静默失败
- 当前桌面联调的首要基线是 `cargo run`；`cargo tauri dev` 作为后续本机或 CI 的补充验证项，不与首轮白屏修复绑在同一通过条件里

## 6. 状态管理要求
必须拆成以下领域 store：
- `appStore`
- `selectionStore`
- `chartStore`
- `syncStore`
- `boardBuildStore`
- `settingsStore`
- `noteStore`

要求：
- 每个 store 只负责一个领域
- 输入表单状态不得和图表刷新状态共用同一大对象
- 不允许再出现旧版“一次 setState 导致整页重渲染”的模式
- 主窗口与设置窗口只通过明确消息同步，不共享可变对象引用

## 7. 图表实现要求
### 7.1 图表实例
- 全应用只维护当前主图的单实例图表
- 只在首次进入主图区时创建实例
- 后续仅允许：
  - `setData`
  - `update`
  - overlay 更新

### 7.2 禁止的图表行为
- 切目标时重建实例
- 切范围时重建实例
- 切日 K / 周 K 时重建实例
- 切板块算法时重建实例
- 盘中更新时重建实例

### 7.3 数据来源
前端只消费后端标准化结果：
- 历史 bars
- 周 K 聚合结果
- 板块 K 线结果
- 当天 overlay

前端不得：
- 自己聚合周 K
- 自己计算板块历史
- 自己做等权/市值权重计算

- `failed`

`BoardBuildStatusPayload` / `board-build-status` event / `get_board_build_status()` 至少必须同构包含：
- `boardId`
- `name`
- `buildStatus`
- `buildPhase`
- `buildTotal`
- `buildCompleted`
- `buildFailed`
- `buildJobId?`
- `buildMessage?`
- `updatedAt`

`BoardSummary` 至少必须包含：
- `boardId`
- `name`
- `compositionAlgorithm`
- `buildStatus`
- `buildPhase`
- `buildTotal`
- `buildCompleted`
- `buildFailed`
- `buildJobId?`
- `buildMessage?`
- `updatedAt`

`activeTargetNote` / `get_target_note()` 返回至少必须包含：
- `targetType`
- `targetId`

### 8.5 Step 4 契约冻结
为避免前后端在 Step 4 出现 watch 生命周期和 live event 口径漂移，以下契约在前端侧先冻结：

`start_chart_watch(payload)` 至少必须包含：
- `targetType`: `index | board | symbol`
- `targetId`
- `granularity`: 仅允许 `day`
- `boardAlgorithm?`: `equal_weight_v1 | market_cap_weight_v1`

固定规则：
- `range` 不进入 `start_chart_watch(payload)`
- `targetType = board` 且未传 `boardAlgorithm` 时，前端本地请求口径必须归一为 `equal_weight_v1`
- `granularity != day` 时，前端不得尝试启动 watch

`start_chart_watch()` 返回至少必须包含：
- `watchId`
- `started`
- `targetType`
- `targetId`
- `granularity`
- `boardAlgorithm?`
- `intervalSec`
- `marketState`
- `updatedAt`
- `message?`

固定规则：
- 仅当 `started = true` 时，前端才允许把该返回登记为当前活动 watch
- 若 `started = false` 且 `marketState = closed`：
  - 这是正常业务分支，不是异常
  - 前端不得弹错误 toast
  - 前端不得进入自动重试风暴

`stop_chart_watch()` 返回至少必须包含：
- `stopped`
- `watchId?`
- `updatedAt`

`chart-live-update` event 至少必须包含：
- `watchId`
- `targetType`
- `targetId`
- `granularity`
- `boardAlgorithm?`
- `updatedAt`
- `marketState`
- `sourceStatus`
- `overlay`
- `meta`

其中 `overlay` 至少必须包含：
- `tradeDate`
- `open`
- `high`
- `low`
- `close`
- `volume`

补充：
- `updatedAt` 是 live event 新旧判定字段，不允许省略
- `range` 不进入 event payload
- 前端不得自行扩展另一套 live payload 口径

## 9. 板块构建交互要求
### 9.1 `save_board()` 双路径
前端必须兼容：

1. 快路径
- `backgroundSyncStarted = false`
- 立即刷新图表

2. 后台路径
- `backgroundSyncStarted = true`
- 立即显示“板块已创建，后台构建中”
- 不等待完整图表返回

### 9.2 构建状态展示
必须展示：
- `queued`
- `running`
- `succeeded`
- `failed`

至少更新：
- 当前板块行状态
- 主图区空态/构建态
- 状态栏摘要

### 9.3 状态获取方式
- 优先使用 `board-build-status` 事件
- 冷启动恢复或事件断连时，再调用 `get_board_build_status(board_id)`
- 不使用高频全局轮询

## 10. Step 3 前端实施前提
Step 3 不能理解为“前端单独接一下真实接口”。

前端进入 Step 3 之前，后端至少必须先补齐最小真链路：
- `bootstrap`
- `save_board`
- `get_board_build_status`
- `get_chart`

若以上 4 条链路仍然是 scaffold / 样例返回，前端只能做局部重构，不能宣称 Step 3 联通完成。

### 10.1 前端实现顺序
推荐固定顺序：
1. 先统一枚举与 payload 字段
2. 再接后端最小真链路
3. 再重做 `boardBuildStore + chartStore + mainFlow`
4. 最后接 `board-build-status` 事件优先与冷启动补查

### 10.2 设置窗口初始化要求
设置窗口不得复用主窗口 `bootstrap -> 选中态同步 -> loadChart` 流程。

必须拆成 `settings-only` 初始化：
- 只读取设置窗口所需 draft / board editor 数据
- 不触发主图 `loadChart`
- 不触发主窗口整套 bootstrap 刷新
## 11. 盘中更新前端要求
### 11.1 更新范围
盘中更新只允许影响：
- 当前活动目标图表
- 图表标题/来源提示
- 状态栏更新时间
- 当前活动目标的局部状态

绝不能影响：
- 设置窗口表单
- 板块编辑表单
- 笔记输入区
- 非当前活动目标的整页结构

### 11.2 watch 生命周期与归属
- watch 生命周期只能由主窗口 chart/watch store 统一维护
- `range` 不属于 watch key
- watch key 至少必须包含 `targetType + targetId + granularity + boardAlgorithm`
- `targetType = board` 且未传 `boardAlgorithm` 时，前端本地 key 必须先归一成 `equal_weight_v1`
- 非 `board` 目标必须使用固定空值口径，不允许一处用 `undefined`、一处用空串
- 后端 `watchId` 返回前，前端必须先生成本地 lifecycle token / pending token，用于约束异步返回写回
- `start_chart_watch()` / `stop_chart_watch()` 返回写回前，必须先校验该 token 仍对应当前待生效 key
- `chart-live-update` 至少必须校验 `watchId + targetType + targetId + granularity + boardAlgorithm + updatedAt`
- 同一 `watchId` 下，`updatedAt` 早于或等于当前已生效 overlay 的事件，必须直接丢弃

启动条件至少包括：
- 当前窗口为主窗口
- 当前目标存在
- 当前粒度为 `day`
- 主窗口可见且应用未进入后台
- 当前目标最近一次 `get_chart()` 已成功写入 chart store，且仍匹配当前选中态

停止条件至少包括：
- 切换目标
- 切换到 `week`
- 切换板块算法
- 主窗口隐藏 / 进入后台
- 主窗口销毁

补充：
- 仅切换 `range` 时不允许重启 watch
- `Settings` 窗口单独获得焦点，但主窗口仍可见时，不应被视为进入后台
- 不允许因为主窗口与设置窗口之间的焦点切换，产生多余的 `start/stop watch` 抖动

### 11.3 更新方式
- 只更新当天最后一根 bar
- 不重新请求整段历史
- 不重建图表
- 不因为盘中事件触发主窗口整页更新

补充：
- 若因 `range` 切换、页面恢复或受控补偿触发 `get_chart(day)`：
  - 响应写入前必须先校验该请求仍匹配当前选中态
  - 响应写入 store 前必须再次与当前活动 overlay 做只读合并
  - 不允许让晚到的历史响应覆盖已生效的 live patch
- `week` 视图不得临时合并 `day` overlay

### 11.4 错误与降级
- 必须区分 `start_chart_watch` 失败、`stop_chart_watch` 失败、`chart-live-update` 长时间未到、以及 `started = false, marketState = closed`
- `marketState = closed` 时显示轻量“当前非盘中时段”提示，不按异常处理
- 保留当前最后一次成功图表，不清空主图
- 不自动切回 mock / fallback
- 不因 watch 失败把主图状态改成全局失败
- 联调前必须确认后端已移除 scaffold / sample live event 路径；若后端仍返回 sample overlay，则前端只能做预改造，不能宣称 Step 4 完成

## 12. 输入稳定性要求
新前端必须从结构上规避旧版这些问题：
- 设置页输入丢焦点
- 板块编辑输入中断
- 笔记输入过程中被自动刷新打断

硬性要求：
- 输入组件挂载后生命周期稳定
- 自动保存不得重建输入节点
- 后台状态变更不得打断当前输入

## 13. 性能要求
前端必须达到：
- 冷启动后主窗口快速可交互
- 缓存命中后切图 `< 100ms`
- `save_board()` 后台路径返回后，主窗口不卡死
- `50` 成分股板块构建期间，主窗口与设置窗口仍可操作
- 连续盘中更新 `30` 分钟不出现整页卡顿和输入打断

### 13.1 针对旧版卡顿问题的固定解法
- 用领域 store 拆分替代整页大状态树，避免设置输入、笔记输入和图表更新互相误伤
- 用单实例图表控制器替代“切一次图重建一次实例”，切目标、切粒度和盘中 overlay 都只更新数据通道
- 用 `settings-only` 初始化 + `settings-saved` 目录级补查替代“保存设置后重放主窗口整套 bootstrap”
- 用板块后台构建、冷启动补查和局部状态推进替代 `save_board()` 同步串行阻塞 UI
- 用 `watchId + updatedAt` 的归属 / 去重规则替代“晚到旧事件直接回写当前图”
- 用局部缓存失效替代全量 `cache.clear()`，避免局部变化放大成全局卡顿

## 14. 前端测试要求
### 14.1 功能测试
- 指数、板块、个股切图正确
- 日 K / 周 K 切换正确
- 等权 / 市值切换正确
- 笔记保存与恢复正确
- 设置窗口独立打开与保存正确

### 14.2 回归测试
- 输入持续进行时不丢焦点
- 图表不重建
- 板块构建中切目标不报错
- 设置窗口输入不被后台更新打断
- 盘中 overlay 只更新当前图表
- 切换 `range` 不重启 watch
- 切换目标后旧 watch 的晚到事件不会污染当前图表
- 同一 `watchId` 下乱序旧事件会被 `updatedAt` 丢弃
- `marketState = closed` 不触发错误风暴或整页重载

### 14.3 视觉验收
- 与旧版 UI 规格一致
- 主图始终是唯一视觉中心
- 左栏保持纯导航
- 状态栏口径一致
- 控件层级、间距、字号、颜色与旧版基线对齐
