# 前端最终业务收口清单

## 1. 目标
这份文档用于收口 `new_stock` 当前剩余的最后一批业务需求。

本轮做完后，前端侧不再继续扩需求，默认进入：
- 联调收口
- 测试回归
- 发布准备

本轮前端必须配合完成的业务项只有 4 个：
1. 明确展示“前复权”口径
2. 在设置窗口提供“删除板块”
3. 移除假数据暴露和 mock/fallback 残留文案
4. 完成四大指数的真实显示收口

## 2. 收口顺序
前端固定按以下顺序推进，不要跳步：

1. 先完成假数据与文案清理
2. 再补“前复权”展示口径
3. 再补“指数真实显示”收口
4. 最后补“删除板块”交互

原因：
- 如果假数据和 fixture 文案还留在界面上，后续“前复权”和“指数显示”会被错误状态污染
- “删除板块”是功能补齐，但不影响行情正确性，优先级放最后

## 3. 前端范围总览

### 3.1 本轮前端必须完成
- 图表头部、来源提示、状态栏中的“假数据 / fixture / mock / fallback”文案清理
- 图表口径显示为“前复权”
- 指数显示路径收口为真实指数，不再暴露样例口径
- 设置窗口板块列表增加删除入口
- 删除板块后的主窗口选择态、目录态、图表态正确切换

### 3.2 本轮前端不做
- 不新增新的行情类型
- 不新增分钟 K
- 不改主窗口整体布局
- 不改 Step 1 到 Step 5 已冻结的组件边界
- 不在前端做任何板块聚合计算

## 4. 业务项 A：前复权展示收口

### 4.1 目标
前端必须明确告诉用户：当前主图展示的是“前复权日 K / 周 K”。

### 4.2 必须完成
- `ChartHeader`
  - 在主标题旁或副标题中明确显示“前复权”
- `Chart meta`
  - 若后端返回真实前复权数据，不允许继续显示模糊文案
  - 若后端本轮未提供单独的“复权类型”字段，前端按产品冻结文案展示“前复权”，但不得根据 `sourceStatus` / `providerKind` / `valueMode` 自行推断复权计算逻辑
  - 若后端后续补充独立复权字段，则以前后端冻结契约为准，前端展示必须直接跟随后端字段
- `指数 / 板块 / 个股`
  - 统一沿用“前复权”口径提示

### 4.3 展示规则
- 个股：显示“前复权”
- 板块：显示“基于前复权成分股合成”
- 指数：若指数为真实指数或代理指数展示，也要保持与主图口径一致，不允许出现“除权”或未说明口径

### 4.4 禁止项
- 不允许前端自己推断复权逻辑
- 不允许把“前复权”做成可切换项
- 不允许图表区一处显示“前复权”，另一处仍保留旧“除权 / 未复权 / fixture”文案
- 不允许把“前复权”展示建立在前端自行计算或猜测后端价格口径之上

## 5. 业务项 B：设置窗口删除板块

### 5.1 目标
用户可以在设置窗口删除已存在的自定义板块。

### 5.1A 前置依赖
- 本项以前后端先冻结“删除板块”真实契约为前提：
  - command 名称
  - payload 字段
  - 返回值结构
  - 删除成功后是否发事件、发什么事件
- 在后端契约未冻结前，前端不得自造临时 command 名、临时 payload 或仅做本地假删除
- 若后端本轮尚未交付真实删除接口，则本项状态记为“阻塞后端”，不允许以前端本地模拟通过验收

### 5.2 组件改动
必须涉及：
- `SettingsWindow`
- 设置页板块列表
- 板块编辑区
- 主窗口目录联动

### 5.3 必须完成
- 在设置窗口板块列表中，为每个可删除板块提供删除入口
- 删除操作必须带确认步骤
- 删除成功后：
  - 设置窗口目录立即更新
  - 主窗口板块目录立即更新
  - 如果当前选中的就是被删板块，主窗口必须自动切走

### 5.4 删除后的主窗口切换规则
若当前主窗口目标正好是被删除板块，或当前主窗口虽然在看个股、但 `activeBoardId` 仍属于被删除板块，前端必须按以下优先级切换：
1. 若还有其它板块，切到目录中的下一个板块
2. 若没有其它板块，切回默认指数
3. 切换完成后再请求图表与笔记

补充约束：
- 若当前目标是被删板块下的个股，删除成功后不允许继续停留在该个股视图
- 删除成功后必须同步清理该板块对应的成员缓存、构建态缓存、高亮态与选择态
- 删除成功后若主窗口自动切换到其它板块，`boardAlgorithm` 也必须同步到新板块当前算法，不允许沿用已删除板块的算法状态

### 5.5 必须保证
- 删除过程中不整页重建
- 删除过程中输入框不失焦
- 删除成功后不残留“构建中 / 失败”旧状态
- 删除失败时明确提示，不 silently fail
- 删除最后一个板块时，主窗口能稳定回到默认指数，不出现空白主图区或悬空选中态
- 删除正在构建中的板块时，主窗口与设置窗口都不残留旧 build 状态

### 5.6 禁止项
- 不允许前端仅本地删除、不调用真实 command
- 不允许删除后继续保留被删板块的行高亮
- 不允许删除后主图区停留在已不存在的板块数据

## 6. 业务项 C：清除假数据

### 6.1 目标
前端正式联调、测试、发布口径下，不再暴露 mock / fallback / fixture 的业务假象。

### 6.2 必须完成
- 正式联调与测试口径下：
  - `VITE_ENABLE_LOCAL_FALLBACK` 必须关闭
  - 关闭前端 fallback 只是前端侧前置条件，不等于后端 fixture 已完成收口
- 主窗口和设置窗口中：
  - 不再出现 `mock`、`fallback`、`fixture`、`样例数据` 之类文案
- 指数、个股、板块图表的来源说明：
  - 必须改成真实后端返回的来源口径

补充说明：
- 前端负责清理 UI 文案泄漏与假成功路径
- 后端负责清理 fixture 导入、fixture source、开发期样例口径
- 若后端仍返回 fixture / sample / local fixture source，本项不能判定为“已完成”

### 6.3 需要前端排查的区域
- `commands.ts` 的 fallback 使用路径
- 主窗口 `ChartHeader` / `StatusBar`
- 设置窗口反馈文案
- 指数来源提示
- 空态、错误态、副标题文案

### 6.4 当前最需要清掉的风险
前端当前不能再把以下开发期语义带到正式口径：
- “本地样例”
- “fixture”
- “mock”
- “fallback”
- “代理指数（测试口径）”

### 6.5 禁止项
- 不允许真实命令失败后自动切回本地样例伪装成功
- 不允许 UI 文案还写“真实图表已接入”，但实际上仍展示假数据来源
- 不允许仅通过关闭 `VITE_ENABLE_LOCAL_FALLBACK` 就宣称“假数据已清理完成”

## 7. 业务项 D：完成指数真实显示

### 7.1 目标
顶部四大指数必须完整跑通“点击 -> 请求 -> 图表显示 -> 状态提示”的真实闭环。

### 7.2 必须完成
- `IndexSwitcher` 保持四大指数切换入口
- 点击任一指数后：
  - 主图切到对应指数
  - 标题显示正确指数名
  - 来源提示显示真实口径
  - 状态栏更新时间与图表状态一致

### 7.3 必须校验的四个指数
- 道琼斯 `DJI`
- 纳斯达克 `IXIC`
- 标普 `GSPC`
- 罗素 2000 `RUT`

### 7.4 前端收口要求
- 指数显示必须与个股、板块共用同一图表控制器
- 指数切换不允许重建图表实例
- 指数来源说明不得继续暴露 fixture 口径
- 若后端返回的是代理指数展示，也必须按后端真实 meta 展示，不允许写死旧文案
- 若后端当前仍以代理指数方式返回，前端必须诚实展示“代理指数”口径，不允许包装成“真实指数直连”

## 8. 前端联调清单
前端工程师本轮开发完成后，至少手工回归以下场景：

1. 启动应用，确认无 fallback / fixture 文案泄漏
2. 切四大指数，确认标题、主图、状态栏一致
3. 查看个股与板块，确认图表口径显示“前复权”
4. 打开设置窗口，删除一个非当前板块
5. 删除当前正在查看的板块，确认主窗口自动切换
6. 删除当前正在查看的成分股所属板块，确认主窗口不会停留在孤儿个股视图
7. 删除最后一个板块，确认主窗口切回默认指数且无空白态
8. 删除后重开设置窗口，确认目录与主窗口一致
9. 删除失败时，确认错误提示清晰且界面不乱
10. 指数若仍为代理指数展示，确认来源提示与后端 meta 一致，不冒充真实指数直连

## 9. 前端完成标准
只有满足以下全部条件，前端本轮业务收口才算完成：
- 主窗口、设置窗口中已无 mock / fallback / fixture 业务文案
- 图表口径已明确显示“前复权”
- 四大指数显示闭环完整成立
- 设置窗口可删除板块
- 删除板块后主窗口状态联动正确
- 删除板块相关边界场景（当前板块、当前个股所属板块、最后一个板块、删除失败）全部通过
- 全程无整页重建、无图表实例重建、无输入失焦

- 删除板块交互回归记录
- 指数切换回归记录
- “前复权”口径显示截图
