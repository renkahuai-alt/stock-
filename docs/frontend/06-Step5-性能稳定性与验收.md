# 前端 Step 5：性能稳定性与验收

## 1. 目标
本步骤负责前端最终收口，确保 Step 1 到 Step 4 已冻结的 UI、状态边界、板块构建链路和盘中 watch 链路在真实主路径下稳定成立，并达到测试可接手状态。

Step 5 不是继续扩功能的步骤，而是把以下事情验证并钉死：
- Step 1 的 UI 骨架、窗口入口和挂载方式没有被后续步骤破坏
- Step 2 的本地闭环已完全退出主路径，不再伪装真实成功
- Step 3 的真实数据、板块构建、跨窗口同步和局部更新已经稳定成立
- Step 4 的 watch 生命周期、旧事件丢弃、失败降级和 `market closed` 分支已经稳定成立

补充：
- Step 5 不允许再改布局、控件语义、store 边界、watch key 口径或前后端契约
- Step 5 只能做收口、验证、补齐失败态与修复回归，不能借验收名义继续引入新的架构变化

### 1.1 当前项目进度约束
截至当前仓库状态，Step 5 必须正视以下现实边界：
- 主窗口 / 设置窗口、领域 stores、真实命令、板块构建链路、watch 链路都已接入
- 图表控制器仍处于 Step 1 冻结的“单实例占位实现”阶段，接口固定为 `mount()` / `setData()` / `updateOverlay()`
- 因此本轮 Step 5 只能把“结构稳定性、状态边界、回归风险、证据留档”收口，不能伪装成“真实图表性能终验”

Step 5 需明确拆成两层口径：
1. **结构与稳定性验收（本轮必须完成）**
   - 白屏回归
   - 主路径真实性
   - 局部更新边界
   - 图表单实例语义
   - 输入稳定性
   - 跨窗口同步
   - watch / build 时序防护
2. **真实图表性能终验（仅在真实图表控制器落地后执行）**
   - 真实渲染耗时
   - 拖拽 / 缩放状态连续性
   - 真实盘中 `30` 分钟连续更新下的渲染稳定性

### 1.2 旧版性能坑与本轮验收重点对应
- 旧版“整页重建 / 输入丢焦点”对应本轮的设置、笔记、板块输入稳定性验收
- 旧版“图表销毁重建”对应本轮的 mount 节点稳定、控制器单实例和只走 `setData()` / `updateOverlay()` 验收
- 旧版 `save_board()` 同步串行卡死，对应本轮的快路径、后台路径非阻塞和双窗口仍可操作验收
- 旧版“全量缓存失效 / 轮询风暴”对应本轮的局部刷新、旧事件丢弃和 `range` 不重启 watch 验收
- 旧版“主窗口白屏 / 设置窗口打不开”对应本轮的 `cargo run` 连续冷启动、工具栏“设置”、`Cmd+,` 和启动日志验收

若当前仍是占位控制器，本轮最多标记为“前端达到测试可接手的结构验收状态”，不得写成“真实图表性能终验已完成”。

## 4. 验收范围
Step 5 必须覆盖以下 7 组验收。

### 4.1 首屏挂载与白屏回归
必须覆盖：
- 冷启动后主窗口成功挂载
- 冷启动后设置窗口成功挂载

- 设置窗口不是整窗白屏
- 首屏骨架完整可见
- 工具栏“设置”和 `Cmd+,` 都能打开独立设置窗口

要求：
- 主窗口必须继续通过 `mountMainWindow()` 挂载
- 设置窗口必须继续通过 `mountSettingsWindow()` 挂载
- `Svelte 5` 挂载方式必须继续是 `mount(...)`
- 不允许回退到旧式组件实例化挂载

说明：
- 若出现“进程和窗口标题正常，但内容区整窗白屏”，本轮 Step 5 直接失败
- 白屏是阻断项，白屏未通过时不得继续宣称 Step 3 / Step 4 可验收

- 借验收名义修改控件语义、交互优先级和文案口径

### 4.4 板块构建链路
必须覆盖：
- 快路径保存后立即出图
- 后台路径进入构建中
- 构建完成自动刷新
- 构建失败反馈
- 冷启动恢复补查
- 中途切换目标不误切回

要求：
- 快路径目录更新不能只发生在设置窗口
- 后台路径不能阻塞界面
- 构建状态变化只更新板块行、主图区和状态栏摘要

### 4.5 跨窗口同步
必须覆盖：
- 工具栏“设置”打开设置窗口
- `Cmd+,` 打开同一设置窗口
- 重复触发设置入口时只聚焦既有窗口
- 设置窗口保存鉴权后主窗口状态同步
- 快路径新建 / 编辑板块后主窗口目录同步
- 后台路径由构建事件推动主窗口更新
- 设置窗口关闭 / 重开后草稿和主窗口状态不串写
- 设置窗口获得焦点但主窗口仍可见时，不误判为进入后台
- 设置窗口打开、初始化、保存成功后，不得重放主窗口 `selection / chart / appStore` 主链路

要求：
- `settings-only` 初始化必须只同步 settings 所需目录与草稿数据
- 主窗口收到 `settings-saved` 后，只允许做目录级补查，不允许顺手重拉主图或重放整棵状态树

### 4.6 盘中 watch 链路
必须覆盖：
- `day` 启动 watch
- 切 `week` 停 watch
- 切 `range` 不重启 watch
- 切目标停旧 watch、启新 watch
- 切板块算法停旧 watch、启新 watch
- 窗口隐藏 / 后台时停 watch
- 恢复前台时按当前状态重新评估 watch
- 旧事件丢弃
- `started = false, marketState = closed`
- `sourceStatus = market_closed`
- 设置窗口获得焦点但主窗口仍可见时，不产生多余 `start / stop watch`
- 同一 `watchId` 下乱序旧事件被 `updatedAt` 丢弃
- 晚到的 `get_chart(day)` 响应不会覆盖已生效 live patch

说明：
- 本组场景必须拆成两批执行，禁止把 `market closed` 分支当成盘中 live 分支替代：
  1. **任意时段必测**
     - `week` 停 watch
     - `range` 不重启 watch
     - 切目标 / 切算法启停 watch
     - `market closed`
     - `start_chart_watch` 失败
     - `stop_chart_watch` 失败
     - 旧事件丢弃
     - 晚到历史响应不覆盖 live patch
     - 设置窗口获得焦点但主窗口仍可见时，不产生多余 `start / stop watch`
  2. **仅在真实凭证 + 可验证盘中时段下必测**
     - `day` 视图真实 live update
     - 持续盘中更新
     - warm / cold path 首条 live event 体感差异
- 若当前环境不满足第 2 组条件，只允许将其列为“待盘中补测项”，不得据此宣称 watch 全量验收通过

### 4.7 输入稳定性
必须覆盖：
- 设置窗口凭证输入
- 板块名称输入
- 新增股票代码输入
- 板块成员编辑
- 笔记输入区

这些输入在以下背景变化下都不能丢焦点或被重建：
- 同步状态刷新
- 板块构建状态刷新
- 跨窗口同步
- 盘中 live update

## 5. 性能与质量指标
Step 5 验收必须至少满足以下指标。

### 5.0 测量方法必须冻结
前端性能与稳定性数据不得只靠“感觉还行”。

至少必须记录：
- `debug / release` 口径
- `cargo run / cargo tauri dev` 启动口径
- macOS 版本、机器型号、芯片
- 测试日期
- 是否真实 Longbridge 凭证
- 是否处于可验证盘中时段
- 数据库状态：冷启动 / 已有历史 / 已预热
- `VITE_ENABLE_LOCAL_FALLBACK` 的值
- 是否保留主窗口 / 设置窗口启动日志

至少必须区分：
1. **冷路径**
   - 首次启动
   - 首次首屏
   - provider 未预热
   - 本地缓存未命中
2. **热路径**
   - provider 已预热
   - 当前目标已加载过
   - 图表 / watch / 构建相关缓存已建立

统计口径至少包括：
- `median`
- `p95`
- 最小 / 最大值
- 样本数

要求：
- 每个核心指标至少连续测 `10` 次
- 明显异常值要单独记录原因
- 不允许把冷路径、热路径和盘中 / 非盘中结果混成一个结论

### 5.1 冷启动与首屏
- 主窗口启动后快速可交互
- 首屏骨架可见时间稳定
- 首屏不得出现白屏
- 首次真实 `get_chart()` 不得导致窗口假死

最小观测口径：
- 首屏骨架必须先于首张真实图表出现
- 首屏期间用户可完成基础点击，不出现“程序无响应”

### 5.2 切图
- 缓存命中切图 `< 100ms`
- 非命中切图也必须保持交互可响应
- 切指数 / 板块 / 个股 / 范围 / 粒度 / 算法时不重建图表实例

当前阶段补充口径：
- 若图表仍为占位控制器，本轮至少验证：
  - 图表 mount 节点不被替换
  - 图表 controller 不重新实例化
  - 数据更新只走 `setData()` / `updateOverlay()`
- 只有真实图表控制器落地后，才把“拖拽 / 缩放状态保持”和真实渲染耗时纳入最终阻断项

### 5.3 板块构建
- 大板块构建期间前端可操作
- 构建事件推进期间不触发整页重放
- 构建完成后只刷新必要区域
- 旧 `buildJobId` 或更早 `updatedAt` 的构建事件不会覆盖当前状态

最小观测口径：
- 构建期间可继续切换目标、输入文本、打开设置，不出现明显阻塞
- 当前板块行、主图区、状态栏之外的区域不应跟随构建事件抖动

### 5.4 盘中更新
- 连续 `30` 分钟盘中更新无整页卡顿
- `chart-live-update` 只 patch 最后一根 bar 或 overlay 摘要
- watch 启停不会造成重复订阅或 UI 抖动
- 切换 `range` 后晚到的历史响应不会覆盖已生效的 live patch
- 同一 `watchId` 下乱序旧事件会被 `updatedAt` 丢弃

当前阶段补充口径：
- 若当前环境不满足“真实凭证 + 可验证盘中时段 + 真实图表控制器”三项条件，则：
  - 只验证 `closed / failed / stale event / late history response` 等结构性风险
  - 将 `30` 分钟盘中连续更新记为待补测项
  - 不允许用 `market closed` 正常分支替代真实盘中 live 验收

## 6. 硬性阻断项与禁止项

### 6.1 阻断项
出现以下任一情况，Step 5 直接失败：
- 主窗口白屏
- 设置窗口白屏
- 主路径静默 fallback
- 图表实例重建
- 输入持续过程中失焦
- 后台构建或盘中更新触发整页重建

### 6.2 禁止项
- 不允许整页重建
- 不允许图表实例重建
- 不允许输入丢焦点
- 不允许主路径静默 fallback
- 不允许盘中更新触发 `bootstrap()` 或全量 `get_chart()` 风暴
- 不允许设置窗口重新走主窗口状态树
- 不允许快路径只在设置窗口本地成功、主窗口无变化
- 不允许在 Step 5 再改布局、store 边界、watch key 口径或 Step 3 / Step 4 已冻结契约
- 不允许把 `Svelte 5` 入口重新改回旧式 `new Component(...)`

## 7. 验收矩阵
Step 5 必须至少逐项验证以下场景。

### 7.1 首屏挂载与白屏回归
- 连续启动应用 `3` 次
- 每次都确认主窗口非白屏
- 打开设置窗口，确认设置窗口非白屏
- 通过工具栏“设置”与 `Cmd+,` 分别打开设置窗口
- 重复触发设置入口，只聚焦同一设置窗口
- 主窗口与设置窗口来回切换，确认主窗口不掉回白屏

### 7.2 冷启动与主路径
- 冷启动后主窗口可交互
- 冷启动后当前目标图表可正常显示
- 真实命令失败时能看到明确错误，而不是 silently fallback

### 7.3 切图与图表实例
- 切指数
- 切板块
- 切成分股
- 切 `1M / 3M / 6M / 1Y / 3Y / ALL`
- 切 `day / week`
- 切 `等权 / 市值`

要求：
- 图表实例不重建
- 响应晚到时不覆盖当前最新目标
- 若当前仍为占位控制器，本轮必须改为验证：
  - mount 节点不替换
  - controller 单例标识稳定
  - 更新只走 `setData()` / `updateOverlay()`
- 只有真实图表控制器落地后，才验证“当前拖拽 / 缩放状态不被无关更新打断”

### 7.4 板块保存与构建
- 快路径新建板块
- 后台路径新建板块
- 编辑已有板块
- 构建失败
- 冷启动恢复正在构建中的板块
- 同一板块新旧两次构建事件交错

要求：
- 主窗口目录同步正确
- 当前板块状态正确
- 主图区构建态 / 失败态正确
- 不误刷新用户已切走的当前图
- 旧 `buildJobId` 或更早 `updatedAt` 的事件必须被丢弃

说明：
- “删除板块”不在 Step 1 到 Step 4 的冻结范围内，不纳入本期 Step 5 验收

### 7.5 盘中 watch
A. 任意时段必测：
- 切到 `week`
- `day -> week -> day`
- 切 `range`
- 板块算法切换时 watch 重建
- 窗口隐藏 / 恢复
- 设置窗口获得焦点 / 返回主窗口
- `market closed`
- `start_chart_watch` 失败
- `stop_chart_watch` 失败
- 旧 watch 事件晚到
- 同一 `watchId` 下乱序旧事件
- 历史 `get_chart(day)` 响应晚到

B. 仅在真实凭证 + 可验证盘中时段必测：
- 盘中 `day` 视图 live update
- 持续盘中更新
- 首条 live event warm / cold path 对比

要求：
- 旧事件不污染当前图
- watch 生命周期稳定
- 主图不清空
- 状态栏反馈轻量且可理解
- `range` 切换不引起 watch 抖动
- 晚到的历史响应不会覆盖 live overlay
- 若当前环境不满足 B 组条件，必须明确列为待补测，不得写成“Step 5 watch 全量通过”

### 7.6 输入稳定性
- 设置窗口输入中收到同步状态刷新
- 设置窗口输入中收到板块构建状态刷新
- 设置窗口输入中收到跨窗口目录同步
- 设置窗口打开与初始化期间
- 设置窗口保存成功并触发主窗口目录补查
- 主窗口笔记输入中收到 live update
- 板块编辑输入中切换别的目标再切回

要求：
- 输入内容不丢
- 光标不跳
- DOM 节点不被替换
- 设置窗口初始化和保存成功后，主窗口当前图表与选择态不应被无关重放

## 10. 完成标准
### 10.1 本轮“结构与稳定性验收通过”
只有当以下条件同时满足时，才能标记本轮 Step 5 通过：
- 前端达到测试可接手状态
- 主窗口和设置窗口都不白屏
- 不再存在整页重建
- 不再存在输入丢焦点

- 主路径真实性已确认
- 白屏回归已通过且有证据留档
- `VITE_ENABLE_LOCAL_FALLBACK` 的验收口径已留档
- 若当前仍为占位控制器或不在盘中时段，所有待补测项已显式列出

### 10.2 “真实图表性能终验通过”
只有在以下条件额外满足后，才允许标记为完整 Step 5 终验通过：
- 真实图表控制器已替换占位实现
- 真实拖拽 / 缩放连续性已验证
- 真实盘中 `30` 分钟连续更新已验证
- 当前文档中所有“待盘中 / 待真实图表终验”项目都已关闭

未满足任一项，都不能把 Step 5 写成“完整性能终验已完成”。
