# 主窗口 UI 视觉收口开发文档

## 1. 文档目标
本文档只面向前端工程师，定义主窗口 UI 的视觉收口要求。

本轮目标不是重新设计产品，而是在**不改变现有布局、不新增多余内容、不改变信息架构**的前提下，把当前界面收口到更稳定、更克制、更接近桌面分析工具的状态。

本文档用于约束：
- 主窗口视觉样式
- 现有控件层级
- 图表容器表现
- 设置入口与状态表达
- 前端交付验收口径

## 2. 硬约束
以下约束为本轮最高优先级，禁止违反：

- 不改主窗口布局
- 不改信息区块顺序
- 不新增业务信息
- 不新增卡片化装饰区域
- 不把当前页面改成“网页首页 / Hero”风格
- 不把主图变成次要区域
- 不以“优化视觉”为理由增加额外说明文案

### 2.1 当前布局必须保持不变
主窗口固定仍为：
- 顶部工具栏
- 四指数横条
- 左侧板块列
- 中间成分股列
- 右侧主图区
- 主图下方区间切换与观点笔记区
- 底部状态栏

### 2.2 当前关键尺寸继续沿用
- Toolbar：`52px`
- IndexSwitcher：`44px`
- StatusBar：`36px`
- 板块列：`132px`
- 成分股列：`188px`
- 主图区最小宽度：`860px`
- 默认窗口：`1440 x 920`
- 最小窗口：`1280 x 800`

## 3. 视觉目标
本轮视觉方向只做“收口”，不做“重设计”。

目标气质：
- 像 macOS 桌面分析工具，而不是网页头图
- 轻、稳、克制
- 图表优先，控件退后
- 选中态明确，未选中态安静
- 弱分隔、弱底色、弱装饰

关键词：
- `SF Pro`
- 浅色背景
- 极弱边框
- 低饱和浅蓝选中态
- 清晰字重层级
- 无大阴影
- 无额外渐变装饰
- 无无意义图形

本轮视觉参考图仅用于前端实现对齐，不代表允许改布局。

参考图：

该参考图表达的是：

- K 线只能出现在图表框内，不允许视觉越界

## 5. 主窗口逐区实现要求

## 5.1 顶部工具栏
目标：从“网页 header”收成“应用级工具条”。

要求：
- 左侧只保留 macOS traffic lights 与应用级标题
- 标题必须短，不使用工程感过强的页面标题
- 中间不放页面说明性大文案
- 右侧仅保留极轻状态与操作按钮
- 操作按钮视觉尺寸可以克制，但真实点击区必须不小于 `44 x 44`

视觉要求：
- 背景接近 `--bg-surface`
- 使用极浅分隔线
- 不使用重边框按钮
- “同步 / 设置”是工具按钮，不应像主要 CTA
- 右侧状态文案弱于标题一个层级

禁止：
- 把工具栏做成 Banner
- 把工具栏做成营销式 header
- 在工具栏放大段状态说明

## 5.2 四指数横条
目标：保留现有位置，但强化“切换入口”身份。

要求：
- 四指数继续放在工具栏下方单独一行
- 不增加额外容器，不做卡片宫格
- 未选中项的文字颜色应与主界面普通正文接近，不能过浅伤眼
- 选中项只需通过更稳的字重 + 下划线 / 底部指示强化
- 未选中项不需要大面积底色
- 四项之间不允许出现明显竖线分隔

视觉要求：
- 选中项：标题、数值、涨跌幅层级清楚
- 未选中项：与主界面其他信息保持一致色强
- 横条本身更像“信息条”，不是 segmented control 玩具按钮

禁止：
- 重新做成圆角按钮组
- 增加多余徽标或图标
- 加强到类似 tab bar 过重选中底色

## 5.3 左侧板块列
目标：保留双列结构，增强列表清晰度。

要求：
- 保持板块列当前宽度不变
- 每个板块项继续是单行列表项，不改成复杂卡片
- 选中项用浅蓝底 + 更稳字重
- 未选中项保持纯净底色
- 列表项左右内边距统一

视觉要求：
- 列标题使用小号大写或弱强调标签风格
- 行高稳定，不要忽高忽低
- 选中项与 hover 态要能区分

禁止：
- 把板块区做成大卡片列表
- 增加额外业务摘要

## 5.4 成分股列
目标：作为板块的从属信息列，保持轻量，不抢主图。

要求：
- 保持位于板块列右侧
- 保持当前宽度不变
- 行项目继续只显示必要信息：代码 + 权重
- 权重为次级信息，颜色弱于代码
- 选中项同样只用轻选中态，不做重色块

视觉要求：
- 列内字重统一
- 代码可略强于权重
- 权重右对齐，保证纵向扫描整齐

禁止：
- 在列表项中增加更多指标
- 用过强红绿颜色污染左侧导航

## 5.5 主图区标题与控制区
目标：保持“标题在左、控制在右”，但让控制的分组语义更清楚。

要求：
- 标题区继续包含：
  - 目标名称
  - 次级状态
  - 数据来源提示
- 控制区继续包含：
  - 板块算法切换
  - 日K / 周K 切换
- 板块算法与日周切换继续在同一水平区域，但要有明确分组感
- 板块算法仅在板块目标下可用；非板块目标仍按当前禁用逻辑处理

视觉要求：
- 标题最大、状态次之、提示最弱
- 控件统一用轻量 segmented 风格
- 当前选中项用浅蓝底或浅蓝描边
- 未选中项只保留中性色底
- 控件高度、圆角、字重与区间切换保持统一

禁止：
- 把两组开关做成不同风格
- 让控制按钮视觉上重于标题

## 5.6 K 线图容器
目标：图表是页面绝对主角，但必须安静、干净、被严格收纳。

要求：
- 图表继续位于主图区中央主体
- 图表只允许出现在图表框体内
- 任何 K 线、网格线、overlay、占位层都不得视觉越界
- 图表框使用轻边框和浅底色
- 图表容器圆角保留，但不能过大
- 不再出现 watermark

视觉要求：
- 图表框边界清楚但不抢眼
- 网格线极弱
- K 线红绿维持现有业务语义，但饱和度适当收敛
- 占位态、构建中、失败态必须也被限制在图表框内

交互要求：
- 图表容器必须继续支持历史拖动与缩放
- 不得因数据更新把用户视角强行拉回最新位置
- 图表实例继续保持单实例

禁止：
- 把 K 线画成趋势线
- 让图表视觉溢出容器
- 每次刷新重建图表

## 5.7 区间切换
目标：作为图表辅助控制，弱于主控制组，但风格统一。

要求：
- 保持位于图表下方
- 保持 `1M / 3M / 6M / 1Y / 3Y / ALL`
- 与“等权 / 市值 / 日K / 周K”保持同一套按钮语言
- 当前选中项明确，未选中项安静

视觉要求：
- 高度、圆角、描边、字重与上方切换器一致
- 不增加额外容器说明

## 5.8 观点笔记区
目标：保留当前区域，但做成研究工作区的一部分，而不是普通表单。

要求：
- 位置继续在主图区下方
- 不新增额外说明块
- 笔记输入区域占据主体
- 保存按钮保留，但弱于核心切换控件
- 文本框内容继续本地持久化并回填

视觉要求：
- 外框与图表框属于同一设计语言
- 标题弱于主图标题
- 输入区背景纯净，可长时间阅读
- 不使用重阴影

交互要求：
- 输入过程中不得因同步、构建、watch 更新而失焦
- 不得因为局部状态刷新而秒回写、秒抖动
- 输入光标、滚动位置、选区应尽量保持稳定

## 5.9 底部状态栏
目标：保留底栏，但从“长句子日志栏”收成“轻状态栏”。

要求：
- 继续位于底部固定区域
- 只展示必要状态
- 信息优先级明确，避免一整句挤满
- 文本颜色弱于主内容

视觉要求：
- 与工具栏同属一套轻表面
- 分隔线极弱
- 字号保持小但清晰

禁止：
- 让状态栏承担说明性正文
- 用大量拼接文案制造噪音

## 6. Settings 窗口视觉要求
Settings 窗口不改结构，但要和主窗口保持同一套视觉语言。

要求：
- 继续保持独立窗口
- 左侧导航、右侧编辑区结构不变
- 输入框、列表项、切换按钮与主窗口风格统一
- “板块名称”“新增股票代码”等输入必须稳定可输入

视觉要求：
- 更像系统偏好设置，而不是后台管理台
- 左侧导航克制
- 编辑区留白均匀
- 输入框和 chip 视觉不要太重

禁止：
- 改回 modal
- 增加复杂面板层级

## 7. 样式实施建议
本轮优先通过 token 与组件层收口，不建议大改结构。

建议前端工程师优先收口这些位置：
- `frontend/src/styles/tokens.css`
- `frontend/src/styles/app.css`
- `frontend/src/components/Toolbar.svelte`
- `frontend/src/components/IndexSwitcher.svelte`
- `frontend/src/components/ChartHeader.svelte`
- `frontend/src/components/RangeSwitcher.svelte`
- `frontend/src/components/TargetNoteEditor.svelte`
- `frontend/src/components/StatusBar.svelte`
- `frontend/src/components/BoardList.svelte`
- `frontend/src/components/MemberList.svelte`

实施顺序建议：
1. 先收工具栏和四指数
2. 再收左侧两列和主图区标题
3. 再收按钮体系统一性
4. 最后收笔记区和状态栏

## 8. 前端验收清单
前端完成后，至少自检以下项目：

### 8.1 结构不变
- 主窗口区域分布未变
- 左侧仍是板块列 + 成分股列
- 主图仍是视觉中心
- 未新增无关信息区

### 8.2 风格统一
- 工具按钮、切换按钮、区间按钮属于同一设计语言
- 选中态统一
- 输入框与列表项边框强度统一
- 字重层级统一

### 8.3 图表正确
- 图表为 K 线，不是折线
- 图表严格裁切在框内
- 滑动历史时不会被立即拉回最新
- 数据更新不重建图表实例

### 8.4 输入稳定
- 设置窗口输入稳定
- 板块名称输入稳定
- 新增股票代码输入稳定
- 笔记输入稳定

### 8.5 视觉限制
- 没有多余竖线
- 没有过重阴影
- 没有多余卡片
- 没有网页 Hero 感

## 9. 本轮明确不做
- 不改产品布局
- 不加新模块
- 不增加新的业务文案
- 不改后端契约
- 不借视觉优化做交互重构

## 10. 交付标准
前端工程师交付本轮 UI 收口时，必须同时给出：
- 修改文件列表
- 主窗口前后对比截图
- 设置窗口前后对比截图
- 图表框内 K 线截图
- 输入稳定性自测说明

若出现以下任一情况，本轮视为未通过：
- 布局被改动
- 新增多余内容
- K 线不在图表框内
- 输入再次失焦
- 图表滑动仍被强制拉回最新
