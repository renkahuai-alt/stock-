# 后端最终业务收口清单

## 1. 目标
这份文档用于收口 `new_stock` 当前剩余的最后一批业务需求。

本轮后端做完后，默认不再继续扩业务范围，进入：
- 联调
- 测试
- 发布准备

本轮后端必须完成的业务项只有 4 个：
1. 日线改为前复权
2. 提供删除板块接口
3. 清除假数据并关闭正式路径中的样例依赖
4. 完成四大指数真实显示

## 2. 收口顺序
后端固定按以下顺序推进：

1. 先清除假数据与 fixture 残留
2. 再切换到前复权数据口径
3. 再收口指数真实显示
4. 最后补删除板块能力

原因：
- 假数据不清掉，前复权与指数显示都会被旧数据污染
- 前复权是核心行情口径，优先级高于删除板块
- 删除板块主要是功能补齐，放最后收口风险最低

## 3. 本轮后端范围

### 3.1 必须完成
- Longbridge 日线拉取改为前复权
- 清理现有数据库中的 fixture bars / fixture chart 结果
- 四大指数改成真实指数显示口径
- 新增 `delete_board(board_id)` 正式命令链路

### 3.2 本轮不做
- 不新增分钟 K
- 不新增新的行情源
- 不改现有前后端冻结契约之外的主结构
- 不引入新的云端依赖

## 4. 业务项 A：前复权口径

### 4.1 目标
所有历史日线与周线展示必须统一基于“前复权”数据。

### 4.2 当前问题
当前 Longbridge 日线拉取仍然使用：
- `AdjustType::NoAdjust`

这不符合产品要求。

### 4.3 必须修改
在 `src-tauri/src/services/market_data.rs` 中：
- 将历史日线拉取从 `AdjustType::NoAdjust` 改为 `AdjustType::ForwardAdjust`

### 4.4 受影响范围
以下数据都必须统一切到前复权口径：
- 个股 `daily_bars`
- 个股 `week` 聚合
- 板块合成 K 线
- 指数显示口径（若走指数历史路径或代理指数展示，也必须保持一致）

### 4.5 数据迁移要求
仅改代码不够，必须处理已落库旧数据。

必须完成：
- 标记现有 `NoAdjust` 旧数据不可继续作为正式结果
- 对真实标的触发重新同步 / 重拉历史
- 明确失效旧 `sync_state` / 本地版本判断，不能让旧口径数据继续命中“已最新”
- 受影响的 `board_daily_bars` 需要重算
- 失效相关图表 / 板块 runtime cache，避免前复权切换后仍吐旧图

强制要求：
- 不能只把 `AdjustType::NoAdjust` 改成 `AdjustType::ForwardAdjust` 就算完成
- 必须提供一次性“前复权切换回补”逻辑，或等价的版本化失效方案
- 必须保证已落库的真实 `NoAdjust` bars 不会因为“最新交易日已存在”而被误判为可继续复用

推荐方式：
- 增加一次性“前复权切换回补”逻辑
- 或新增本地版本标记，发现旧口径数据时强制全量回补
- 若无法做精细失效，至少对受影响真实标的清空历史 bars / sync state 后重拉，再重算相关板块物化结果

### 4.6 验收标准
- 任一真实个股日线不再是 `NoAdjust`
- 板块合成日线基于前复权成分股重算
- 前端拿到的个股 / 板块 / 指数图表口径一致

## 5. 业务项 B：删除板块

### 5.1 目标
后端提供正式的板块删除能力，供设置窗口调用。

### 5.2 必须新增
必须新增正式命令链路：
- command：`delete_board(board_id)`
- service：`BoardService::delete(...)`
- repository：板块级事务删除

### 5.3 删除范围
删除板块时，必须在同一事务中处理：
- `boards`
- `board_members`
- `board_daily_bars`

可选处理：
- `target_notes` 中 `target_type = board AND target_id = board_id` 的记录

### 5.4 删除后的状态要求
删除成功后必须满足：
- 后续 `bootstrap()` 不再返回该板块
- `get_board_build_status(board_id)` 对被删板块返回明确错误
- 板块相关缓存失效
- 若该板块存在构建任务或 watch 上下文，不得残留脏状态

### 5.5 事件与联动
删除成功后，必须能让前端刷新目录。

允许做法：
- 复用现有 `settings-saved`
- 或增加目录刷新触发，但本轮优先复用已冻结事件链路

### 5.6 禁止项
- 不允许只删 `boards` 不删成员或板块日线
- 不允许删除后缓存仍命中旧板块数据
- 不允许删除失败却返回成功

## 6. 业务项 C：清除假数据

### 6.1 目标
正式联调、测试、发布路径下，不再依赖 fixture / mock / fallback 伪装真实业务成功。

### 6.2 当前残留
当前代码中仍存在以下开发期路径：
- SQLite debug fixture 导入
- 同步中的 `fixture_only_bars` 分支
- 前端可配置 fallback 路径
- 指数 / 图表 meta 中的 fixture 来源语义

### 6.3 后端必须完成
- 明确区分：
  - `dev/debug` 可选 fixture
  - `test/release` 禁止 fixture 业务主路径
- 提供一次性清理能力，至少覆盖：
  - `daily_bars` 中 `source LIKE 'fixture_%'`
  - `board_daily_bars` 全量清理，或按受影响 `board_id` / algorithm 成组清理后重建
  - 相关 runtime cache

说明：
- 当前 `board_daily_bars` 没有可靠的 provenance/source 字段，不能依赖“逐条识别哪些记录由 fixture 派生”这类实现
- 因此清理策略必须采用“整表清空”或“按受影响板块整组删除后重建”的方式，不能写成模糊口径

### 6.4 推荐实现
建议新增一个内部运维 / 开发辅助能力：
- `purge_fixture_data()`

执行顺序建议：
1. 清理 fixture bars
2. 清理板块物化结果（整表或受影响板块整组）
3. 清理由 dev fixture 导入、当前已无 bars 且未被任何板块引用的孤儿 symbol / sync_state，避免真实同步继续请求 `SIMxx / EMPTYx` 之类假标的
4. 失效相关缓存
5. 执行真实同步
6. 重新生成受影响板块

### 6.5 正式口径要求
- release 验收数据库中不得继续以 fixture bars 作为正式图表来源
- `get_chart()` 返回的 meta 不得继续暴露 `sqlite_fixture / local_fixture_points`
- 指数、个股、板块的 `sourceStatus` 必须回归真实业务语义

## 7. 业务项 D：完成指数真实显示

### 7.1 目标
四大指数必须走真实后端链路，不再停留在 fixture / 占位口径。

### 7.2 必须覆盖的指数
- `DJI`
- `IXIC`
- `GSPC`
- `RUT`

### 7.3 必须完成
- `bootstrap()` 正确返回四大指数目录
- `get_chart(index)` 返回真实可展示图表
- 图表 meta 中的来源说明真实有效
- 指数切图与个股 / 板块共用正式 chart 主路径

### 7.4 当前需要清理的问题
当前图表 meta 里仍有这类开发期语义：
- `providerKind = sqlite_fixture`
- `valueMode = local_fixture_points`

这些都不能保留到正式口径。

### 7.5 指数实现要求
若四大指数需要通过代理指数 / ETF 方式展示，必须满足：
- 口径稳定
- meta 明确
- 前端可理解
- 不再带 fixture 语义

若可直接拿到指数历史，则优先直接用真实指数历史。

### 7.6 验收标准
- 四大指数都可独立切图
- 指数图表不是空白、不是样例数据
- meta 与状态提示不再暴露 fixture 文案

## 8. 联调要求
本轮业务收口完成后，后端必须支持前端完成以下完整链路：

1. 启动应用
2. 看到四大指数目录
3. 点击指数切图
4. 查看个股 / 板块图表为前复权
5. 设置窗口删除板块
6. 删除后主窗口自动切走并恢复正常
7. 正式口径下无 fixture / mock 数据混入主图

说明：
- 本节属于前后端联调 / 验收要求，不等同于后端单侧代码完成标准
- 后端文档中的前端行为要求，应视为联调结果约束，不应替代后端自身交付定义

## 9. 回归测试清单
至少补齐以下测试：

### 9.1 前复权
- 历史拉数使用 `ForwardAdjust`
- 切换前复权后旧数据不会继续混用
- 板块合成在前复权数据下可正常重算

### 9.2 删除板块
- 删除存在的板块
- 删除不存在的板块
- 删除有 `board_daily_bars` 的板块
- 删除后 `bootstrap()` 不再返回该板块

### 9.3 清除假数据
- fixture 数据清理后真实同步可正常运行
- 清理后 `get_chart()` 不再返回 fixture 口径 meta
- 清理后缓存不会继续吐旧图

### 9.4 指数显示
- 四大指数都能返回有效图表
- 指数来源 meta 正确
- 指数切换不报错

## 10. 完成标准

### 10.1 后端完成标准
只有同时满足以下条件，本轮后端开发才算完成：
- 历史日线已切到前复权
- 删除板块正式可用
- 假数据已从正式路径清除
- 四大指数真实显示闭环成立

### 10.2 联调完成标准
进入联调验收后，还必须满足：
- 前端无需再为这 4 项做额外业务兜底
- 前后端对前复权、指数来源、删除板块后的刷新与切图行为达成一致

## 11. 交付物
后端本轮交付至少包括：
- 相关 command / service / repository 代码
- 一次性数据清理或迁移方案
- 删除板块回归结果
- 四大指数联调结果
- 前复权切换验证记录
